# R21 scope review: a CPU capacity diagnostic, not a new model

Root accepts the final R21 section of `r21_ASTRA_DESIGN.md` for implementation and synthetic CPU tests. The failed R20 method remains closed. R21 uses all 576 previously available development questions and their six native-depth candidate score vectors. It adds no model forward, training, external information or other benchmark.

The two per-label linear programs measure the score convex hull H6 and its separate R6-augmented upper bound H7. Gold labels are used only for retrospective evaluation of a finite score family; no oracle weights or controls may be deployed. The final mutually exclusive H6 categories and the original 20%/10%/1% diagnostic criteria are fixed. A positive result establishes capacity only; a negative result limits this family only. Neither outcome establishes whether hidden states contain the facts or whether a label-free selector is learnable.

Before the full oracle calculation, Sol must freeze the implementation and exact input hashes, pass synthetic tests, obtain Astra/Root source review and publish the definition for independent readback. Original input identities, ordering, normalizers and shared-depth exact parity are mandatory; a mismatch stops the diagnostic. No newly chosen subset, model variant or solver search is authorized.

Numerical certification must use independently recomputed feasible simplex witnesses, not merely a solver success flag. Recover primal weights and nonnegative dual mixture weights, reject materially invalid values and normalize without an arbitrary epsilon. Compute lower=min(Aw) and upper=max(A^T lambda), together with a documented conservative FP64 error allowance covering dot products and normalization (or a stronger exact-arithmetic certificate). Classifications use certified lower/upper bounds and the unchanged 1e-8 threshold; an excessive residual or gap makes that case undetermined. Keep raw solver outputs and both witnesses for audit.

Execution is CPU only, at most 20 minutes including checks and exit, with no new GPU ledger use. The original total remains 18,472.29435229581/21,600 GPU-worker seconds. Any exception or incomplete execution must remain visible and cannot be replaced by a different cohort or solver setting. Existing folders and immutable old records are retained. Another deployment proposal requires a separate concrete mechanism review after these diagnostic results; this authorization does not claim that proposal already exists.

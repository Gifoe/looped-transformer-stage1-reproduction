# R25：24题 pilot 的检出能力与资源决策审查

状态：任何 R25 实现/真实 key/query 特征之前的设计审查。未修改 v1/v2 算法、控制或当前生效 gate；本文提出的分阶段规则须 Root 明确采纳并在执行前冻结，否则仍以原合同为准。没有运行模型；下列概率仅为二项分布算术。

## 24题强门槛不能检验原目标大小的效果

24题包含 R6 错误10题、正确14题。设每个错误题被救回概率 r、每个正确题受损概率 d，在同质且题间独立的理想化模型下，R~Binomial(10,r)、D~Binomial(14,d)，本 cohort 预期净提升为 (10r−14d)/24。仅原 R6 gate 的通过概率为 P(R>=2)P(D=0)；其他控制与旧收益要求只会进一步降低总体通过率。

以原 ARC 目标净+15/1172=1.2799个百分点为情景，令 (10r−14d)/24 等于该值：

| d（正确题损害率） | r（错误题救回率） | 无 rescue 概率 | 至少2 rescue且0 damage通过率 |
|---|---|---|---|
| 0 | 3.0717% | 73.20% | 3.60% |
| 1% | 4.4717% | 63.29% | 6.16% |
| 3% | 7.2717% | 47.00% | 10.54% |

这些不是该方法真实 power 的估计：24题不是新的随机独立样本，开发反复复用、题间异质，且原 ARC 的 R6 错误比例不同。它们只是明确反例：即使存在目标量级的正效果，原 gate 也很可能不通过。原 gate 更适合寻找少量预算下明显的大效应，不能充当“没有约1.3pp提升”的判决。

在同一理想模型里，10个错误题零 rescue 的单侧95%精确上界为 r=25.89%，远不能排除3.07%的救回率。因此24题完全无预测变化不是科学上的普遍无效证据。R20/R23实际没有 rescue、损害旧收益及未胜必要控制仍是各自已观察到的负证据；本审查不更改其结果、不重开其方法或合并这些相关 pilot 作新的独立统计检验。

## 可接受的阶段定位与事前继续规则

建议将24题明确定位为**完整性、真实成本与明显损害筛查**，而不是原目标效应的正式验证。若 Root 采纳，可事前采用如下替代的阶段决策；必须整体替代资源推进语义，不能运行后挑旧 gate 或新规则中有利者。

1. 完整性、全24、预算正常退出、所有 exact parity、no unmatched 等硬要求原样保留。任何失败不解封 partial，不能称算法无效，也不自动重跑。
2. 原严格科学/资源 gate 全通过：记为“原探索 gate 通过”，只允许具体后续预算审查，不宣称最终目标达成。
3. 严格 gate 未通过，但 primary 对 R6 net>=0、旧独有纠错全部保留：最多记为“未识别收益，未触发预设损害停止；可考虑完整开发评估”。不要求此时已经胜出所有控制，也不把 controls 晋级；同样不宣称 pass、正面方法证据或效果存在。所有实际损害数仍完整报告，net>=0不等于零损害。
4. primary net<0 或丢失旧独有纠错：作为保守资源筛选停止该 pilot 后续，不表述为统计证伪全 ARC 小效应。

第3项明确允许零 rescue/零 damage/全预测相同进入**资源可行性**审查，避免把无力小样本当作不存在小效应的证明；它不允许自动进入下一数据阶段。只有完整后续成本已经可支付，或用户批准具体缺口预算，才可进入完整576开发。不得依据24效果改样本、方法、阈值、排序或删控制。

最终全量 confirmation517、validation299、ARC1172、原净纠错目标、旧收益与控制/参考稳定要求均不因这一定位改变而放宽。完整576也仍是被复用的开发集，不能充当最终独立确认；更不能把“通过继续规则”写成“通过方法 gate”。当前并无具体全文576新阈值锁，后续正式执行前仍须冻结该阶段与全量后续规则，禁止看576结果后补门槛。

## 现有资源无法支持完整链；改变 pilot 定位不改变算术

剩余原 GPU-worker 预算2958.2004723269492秒。一次300秒 pilot 后最坏剩2658.2004723269492秒。按历史粗估，完整576开发约1900秒起，单独开发可能装得下，但尚未包括143-key全 V检索/新审计，必须看本次实际拆分 profile。完整517 confirmation约1705.4、299 validation约1470、1172 ARC约5740秒起，整个后续约10815.4秒起。甚至576+517两阶段约3605.4秒起，已经超过当前全部余额。

因此，“在剩余GPU内跑完整576并按原全量confirmation/val/test决定”目前不能承诺。只是把24改成工程 pilot，并不会让完整链可行。上述继续规则的资源条件当前没有满足；不得自动扩预算或缩小任何 cohort。允许先跑576只能是一项另外明确冻结的、未能完成用户最终目标的开发证据任务，不能包装成已具备完整交付路径。

若采用第3项推进路线，原“只有严格正面24才可提预算”也必须显式修订：否则规则在工程上永远不能推进。修订只能是在24完整 profile 后提出**具体的无效果保证的完整评估预算**，说明24结果未证明收益及为何值得追加，不能把未负面的 pilot 称正面来绕过。Root 可选择保留原仅强阳性预算策略；若保留，应坦率称为资源限制下优先筛大效应，而不是认为小效应已被排除。

我的建议：科学解释采用上述区分；是否支付小效应完整检验的成本由具体资源决策决定。现阶段不宣称原强 gate 有足够 power，不擅改它，不为满足预算缩小517或最终标准，也不因尚余GPU而自动追加实验。

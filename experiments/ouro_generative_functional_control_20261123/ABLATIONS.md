# 消融与开发集决策

以下数值用于选型。独立确认集结果和同题区间在 `GENERATION_RESULTS.md` 及 `results/CONFIRMATION.csv`。

## 从排序到逐 token 训练

旧排序控制器和两组重训共用同一批 1,119 道 CSQA 官方训练题、282 次更新、每步的题号与循环深度。生成训练给完整答案与 EOS 提供监督，30% 的样本产生大写字母，70% 产生完整选项内容，候选位置按锁定种子置换。这组实验改变了监督以及形成监督所需的提示和选项位置。可用同两组重训直接衡量加入候选辅助的影响。

| K4 开发指标 | Native | 历史排序 | 仅生成 | 生成及排序 |
| --- | ---: | ---: | ---: | ---: |
| CSQA 宽松字母，n=160 | 61.25% | 66.25% | 63.75% | 65.00% |
| CSQA 完整选项文字，n=160 | 55.00% | 35.00% | 63.75% | 63.75% |
| 两个 MC 任务严格字母宏平均 | 2.08% | 0.52% | 71.98% | 73.13% |
| 两个 MC 任务候选 acc_norm 宏平均 | 45.00% | 56.35% | 46.98% | 52.19% |
| 六项生成语义宏平均 | 50.39% | 47.26% | 58.69% | 58.09% |

严格格式改善与内容正确率改善同时出现。仅放宽大小写的 CSQA 字母指标仍以历史排序领先，说明格式纠正和问题求解可以分开变化。加入候选辅助使开发集候选 acc_norm 恢复 5.21 个百分点，CSQA 完整内容未变，OpenBookQA 完整内容下降 5.21 个百分点。

这组对照匹配训练题和更新次数。历史排序实际使用 493,340 骨干填充 token×loop，训练耗时 29.17 秒。用时不计入本轮 GPU 台账。两组新训练分别使用 213,572 和 706,912 骨干填充 token×loop。

## 扩容与排序权重

六来源完整池的生成语义宏平均为 57.99%，比等计算量混合小池高 10.37 个百分点，比 CSQA 生成及排序组低 0.10 个百分点。SQuAD EM 为 76.39%，GSM8K 最终数字正确率为 6.94%。部署指标按独立测试判断。

完整池和前两组新权重的候选 acc_norm 均低于候选保留门槛。第四轮从同一个仅生成权重出发，在同一 1,128 条选择题上，用相同的 282 次更新和相同学习率比较两种排序系数。0.25 组的开发语义宏平均为 59.86%，候选 acc_norm 为 50.94%。0.90 组分别为 58.45% 和 51.67%。扩大排序系数只恢复 0.73 个百分点候选准确率，同时降低 1.41 个百分点的语义正确率。这是局部配对证据，每种系数只有一次固定种子运行。

按开发生成语义优先，冻结 0.25 组作为唯一部署权重。0.90 组权重、训练轨迹和开发预测一并保留。

## 评分和运行机制

逐 token 实际前缀的 logits 与按相同完整前缀的训练路径在 24 个位置逐比特相等。完整序列 teacher forcing 的目标 token log probability 最大误差为 2.38×10⁻⁶。未增加循环或额外模型调用。训练为教师强制，未测试由模型采样前缀的训练。实验保持注入时机、模型大小和限幅一致，观察到的性能差异不能识别 Rank-1 容量上限或更优的写入时机。

开发集最初的文本解析未接受带正确字母前缀的完整选项。在封存确认集前调整，保留初版逐题记录并对同一生成文本重算。确认阶段同时报告严格完整文本与允许特定答题外壳的内容指标。

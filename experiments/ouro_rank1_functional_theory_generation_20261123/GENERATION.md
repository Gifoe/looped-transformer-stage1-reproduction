# 真实生成的时机、剂量与训练目标

选择题使用历史的完整词表贪心解码和停止规则，最多 6 个 token。开发集为 ARC Train 的固定 256 题与 OpenBookQA Validation 500 题。每个单元格为真正生成后按历史选项解析器得到的答对数。未在 ARC Validation、OpenBookQA Test 或内容生成结果上选择方法。 [逐轮开发数据](results/dev_round1/DEV_RESULTS.json) [第二轮数据](results/frozen/DEV_RESULTS.json)

| 方法 | ARC Train 开发 K1–K4（n=256） | OpenBookQA Validation K1–K4（n=500） |
|---|---|---|
| 原 Rank‑1 T1 | 128 / 199 / 221 / 225 | 167 / 327 / 386 / 392 |
| 首步 | 128 / 199 / 221 / 225 | 167 / 327 / 387 / 392 |
| 前两步 | 128 / 199 / 221 / 225 | 167 / 327 / 387 / 392 |
| 只控制续写 | 124 / 190 / 220 / 223 | 174 / 310 / 387 / 395 |

| 后续幅度降至 0.15 | 128 / 199 / 221 / 225 | 167 / 327 / 387 / 392 |
| 原剂量低于 0.43 才编辑 | 124 / 200 / 220 / 222 | 174 / 327 / 387 / 395 |
| 历史 Rank‑1 T2 | 116 / 215 / 228 / 227 | 169 / 388 / 404 / 398 |
| 新联合拟合 | 139 / 203 / 220 / 223 | 203 / 368 / 397 / 395 |

只关闭后续写回的总体正确数几乎不动，降低首步上限和更换训练目标才在两个数据集上都改善 K2–K3。OpenBookQA K2 原 T1 合法输出 471/500，0.25 上限与 T2 都为 500/500，答对数分别增加 13 和 61。两种改变产生不同的正确数，即使它们有相同总体合法率。需用逐题比较分解格式恢复和内容选择，以免把净结果直接归因于格式。联合训练在 K1 提升较大，K3–K4 在 ARC 开发组有下降。锁定规则要求同一实验权重系列覆盖预算，按两域最小增益选择。冻结方案为 K1 继续 T1，K2–K4 改用原有 T2。新拟合权重和负结果均保留。 [冻结选型](results/frozen/PROPOSAL.json)

## 完整 GSM8K 内容生成

完整 Test 1,319 题在 K4 使用上一轮的零样本提示、最多 256 token、贪心解码、同一缓存路径和固定评分规则。宽松数值抽取下，原 T1 为 231/1,319（17.51%），T2 为 257/1,319（19.48%），净增 26 题。配对救回／退化为 137／111，净差 +1.97 个百分点 [−0.38, +4.32]。相比历史最强同协议 LoopCD Adaptive 的 224/1,319，T2 高 +2.50 个百分点 [−0.08, +5.00]。两区间均跨零。严格 `####` 正确数由 0 变 1，格式合规仍很低。平均生成长度从 185.83 降至 167.95，触顶从 401 降至 292。 [原文、评分和配对](BENCHMARK_RESULTS/gsm8k/SUMMARY.json)

## 完整 MMLU‑Pro 迁移

完整 Test 12,032 题在 K4 用同一零样本字母作答协议。原 T1 答对 4,354，T2 答对 4,547，差 +1.60 个百分点 [1.14, 2.07]。救回 509、退化 316。严格单字母正确数和宽松正确数一致。有效输出增加 261，达到 12,021。两种策略都输出合法答案的 11,760 题上，旧 4,354 正确，新 4,478 正确，净增 124。其余净增 69 来自此前的无效输出。较历史同协议最优的 Rank‑8，T2 净增 95 题，差 +0.79 个百分点 [0.32, 1.25]。平均输出长度由 1.158 token 降到 1.006。 [原文、评分和配对](BENCHMARK_RESULTS/mmlu_pro/SUMMARY.json)

## 权重与运行成本

T2 与 T1 的写出方向余弦为 0.847，编码向量余弦为 0.987，未限幅外积的范数比为 0.997。联合拟合的对应余弦是 0.940、0.996。T2 保持秩一和近似的总未限幅尺度，同时更显著地改变输出方向。未做独立交换，不能由向量余弦判定哪一项改变造成准确率收益。两臂使用同样的 Loop 预算和每步预测调用。GSM8K 和 MMLU‑Pro 完整两臂作业分别用 1,198 秒和 720 秒，包含加载、评分和归档。每分片的时延、显存和 token 数随结果保存。 [权重与作业审计](FINAL_AUDIT.json)

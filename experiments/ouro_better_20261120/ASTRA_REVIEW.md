# Astra decision, iteration 1

**Run a shared recurrent adapter with counterfactual option-order consistency.** Ouro must retrieve the same answer content when the options move and emit the new bound label. The proposed bottleneck is the dependence of the recurrent decision on arbitrary option position. Improving the gold letter on one ordering alone cannot establish that this bottleneck changed. This is a narrow multiple-choice hypothesis and an experimental proposal, not a demonstrated general reasoning improvement.

## Frozen first iteration for Sol

1. Freeze before collecting fresh scores. Primary task is zero-shot displayed options, single letter, deterministic standard prompt, no demonstrations. Convert labels to single tokenizer continuations with an explicit parity check. Primary deployable exact accuracy uses one unrestricted greedy next token and a fixed letter parser, with invalid continuations scored wrong. Report also restricted letter argmax, original-order accuracy and a content-target teacher-forced contrast separately. One canonical view per question in deployment. Do not average rotations, rerank or call a second readout.

2. Use official training partitions only. Default split first separates normalized question-text/choice-set duplicate clusters, excludes prior experiment and demo IDs/content from new dev/confirmation, resolves close overlaps, then SHA-256 orders clusters with salt ouro-better-v1. Use 512 ARC-Challenge train questions for fitting, next 128 unused for the first development gate and reserve 256 fresh for confirmation, shrinking fit first if availability requires. Prior training exposure may be assigned to fit only. Freeze a separate 384 previously unused OpenBookQA official-train examples as cross-domain confirmation with no tuning; freeze a 128-question disjoint same-domain OpenBookQA development cohort only if required to balance protocols, and do not use it to claim blind transfer. Never open official test records. Check data lineage across sources with the official held-out sets staying sealed. If decisions or data partitions were frozen in the main goal earlier, honor the stricter constraints, record differences before scores, and preserve an unexamined transfer confirmation set. Record splits, duplicate criteria, revision, rows available, rejections and hashes.

3. For each train item make original and a seeded nonidentity cyclic rotation, remapping labels and gold content. Each example supplies two real prompt forwards. Use shared rank-8 alpha-16 LoRA on recurrent q_proj and v_proj at all 24 physical layers, zero-init effective update. Same adapter at every loop and budget, frozen embedding, norm and unembedding. In one true six-loop trajectory observe K=1,2,3,4,6. Mean full-vocabulary cross-entropy on each correct label at each exit and both views. Add one times mean Jensen-Shannon divergence between the two softmax distributions over candidate-letter logits remapped to common content order at each exit (temperature 1). Gradient flows into both views. This makes a falsifiable objective beyond ordinary multiexit supervision. FP32 accumulation for loss and merge, BF16 dense weights after merging. Deploy the same merged weights at all depths. Reversibly merge in memory to avoid duplicating a multi-GB checkpoint.

4. Mandatory comparisons share identical prompts, views, train item counts, updates, common seed, parameter targets, depth weights and training compute ledger. Ordinary LoRA uses only the multiexit CE, including both views. Distillation adds KL from frozen base K6 candidates to each shallower exit in the same view, weight 1 and temperature 2 with T-squared scaling; cache teacher candidate logits offline. Loop Dropout uses CE with the paper's independent per-loop adapter-application masks, inverse survival scaling and p=0.5, fully enabled at deployment, following its gate-sharing convention. Use the resource-matched rank-8 setup and disclose differences from the paper's rank-16 seven-projection experiments. [Loop Dropout method and defaults](https://arxiv.org/html/2609.34218v1). Initial screen uses AdamW 1e-4, effective batch four question pairs, one epoch over 512 items (128 updates), grad clip 1, weight decay 0, seed 101; one terminal checkpoint per arm. Microbatch and native activation checkpointing may vary for memory; equivalent paired views must share a loss graph. Any subsequent tuning requires independent development with equal opportunities across arms, never confirmation tuning.

5. At K=1 use Native. For each K=2,3,4,6 run actual Native and Fixed/Adaptive/Hidden LoopCD at that depth with native K1 reference and published formulas, including the full-vocabulary top-two in Adaptive. Freeze the strongest on dev per depth and still tabulate all on confirmation. Also compare against the observed maximum of all four on confirmation for a claim of beating the strongest; give paired intervals against each, avoiding a standard-error calculation that ignores the selection. No depth substitution. K6 requires six real 24-layer passes, identical recurrence, normalization and step positions to a manually unrolled six-pass reference. No synthetic intermediate from K4, accidental K4 halt, learned depth ID outside its valid domain, or duplicated terminating layers. For a claim that extra depth improves performance within the candidate, separately compare candidate K6 against K4; improvement relative to Native K6 alone only establishes a same-depth gain.

6. Development screen is deliberately cheap. Compare candidate with the strongest native-family comparator: require positive original-order exact accuracy differences at all five depths, positive mean over depths relative to ordinary matched LoRA, and increased same-content agreement across a separately frozen order pair averaged over depths without sacrificing original-order accuracy. If this fails, log the full table and stop this hypothesis before confirmation. Better transfer of a label format is a plausible alternative; log invalid-output rate, unrestricted and restricted win/loss matrices, content-target contrast and correctly remapped gold. In the paired diagnostic add hash-balanced random content permutations, including noncyclic ones, independent of training rotations. If only validity or consistency improves, no inference of improved reasoning. For a passing model diagnose recurrence on dev by running candidate for loop one then native for remaining loops and the reciprocal model switch, with full-state and same-model sham parity. Compare K4/K6 effects against full candidate, Native and the CE-only arm. Restricted, dev-only extra forwards are bookkeeping for attribution, excluded from deployed method costs.

7. After passing dev freeze, run the same checkpoint and baselines once on both sealed cohorts. Require positive exact accuracy increments at every K against appropriate baselines in each cohort, paired per-question uncertainty, and report all training baselines. Formal joint same-depth performance claim requires one-sided paired evidence for each constituent contrast (intersection-union, including each baseline at that K); exploratory endpoint or arm claims use explicit multiplicity handling. With inadequate precision report inconclusive. Mechanism-specific added value requires improvement over matched CE training, accurate remapping and actual generation gains; superiority to other trained methods requires explicit comparisons. Report each cohort separately, never substituting pooled means for failed depths.

8. For all arms profile actual independent stops at each K at batch one, common BF16/device/attention backend/cache width and prompts. Warm up, interleave order, sync CUDA, measure paired median and p95 over at least 64 fixed prompts with repeated passes, first-token latency, per-token decode on equal-length continuations and separate end-to-end natural-length generation, allocated peak, tokens, layers and vocabulary projections. For LoopCD charge all real K1 heads/mixes. Candidate must match Native's deployment operation count, dense dimensions, output-head count and cache and have upper paired 95% bound on median equal-work latency ratio at most 1.05. This bound is timing tolerance, not proof identical wall time. Report exact counts/margins and model hashes. A fast per-exit readout of a full K6 run is not standalone latency. Keep tiny adapters and per-item outputs, stream large intermediates and never delete other runs.

Decision rights return to Sol after this memo. A negative dev result is a mechanism rejection for this implementation. Any redesign uses a distinct frozen dev experiment, without exposing confirmation. No model run or GPU modification was performed for this review.

# Reproduce E4/E5 local causal experiments

These experiments use complete model forwards at physical L18: adjacent-loop KV access, natural-K2 Q/KV factorials, actual R-state-to-attention mediation, matched late-loop mediation, and a preregistered 128-question cross-question confirmation. No cached suffix approximation is used. A validated earlier generating-layer E3 path is not assumed. Completion and actual coverage are determined by the corresponding receipts and independent audits.

The collector is `results/code/runner.py`, its scoped hook is `observer.py`, and `attested_runner.py` adds actual loaded-module source attestation. Independent analysis is implemented separately by Astra. Runtime inputs contain no current-question gold label; the original fixed few-shot example answers remain in the prompts. Current-question labels are joined only by the independent analysis. `inputs/train64_selection.json` and `inputs/validation_selection.json` freeze the selected IDs and unrelated-source cyclic donors.

1. Place the fixed Ouro model snapshot in a work directory named `model/`, alongside copies of `runner.py`, `observer.py`, and `attested_runner.py`. The checkpoint must have SHA256 `58872a72616c736595b8b7662079c5b12c5a162ec16eae94f21c348dfa9885af`; the collector refuses other bytes. Use the Python/PyTorch/CUDA package versions saved under `results/provenance/`. The GPU used here is an RTX 4090; a different GPU is a separately named hardware refresh and must be compared with these native baselines.
2. Decompress the preserved `inputs/runner_inputs.jsonl.gz` without retokenizing, and copy the frozen cohort manifests. Set `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, and `TOKENIZERS_PARALLELISM=false`.
3. Run `python -u attested_runner.py --inputs inputs/runner_inputs.jsonl --cohort inputs/train64_selection.json --output RESULTS_PILOT`, followed by the same command with `inputs/validation_selection.json` and a separate output directory. The actual original shell commands and launch timestamps are retained in each original output directory. Use `--phase collect` or `--phase replay` only when that phase is desired. Existing completed questions are verified and reused; an identity/source/cohort mismatch stops the run. Do not edit code and resume into an existing namespace.
4. Run `astra_independent_audit.py --results RESULTS --labels inputs/all_labels.jsonl --cohort COHORT --output AUDIT.json`; run `astra_geometry_audit.py` as described in its CLI for independently recomputed descriptive geometry and control norms. Both audit scripts are independent of the producer's metric functions.

Each question has a native JSON file, compact BF16 native/intervention tensors, and a result JSON file. Scores are FP32 log-softmax of the model's BF16 logits. Raw candidate logits and FP32 logsumexp are retained for score verification. Full-vocabulary endpoint hashes support exact within-run identity checks. Original complete input IDs, targets, metadata hashes, model/source hashes, actual SDPA argument descriptors, exact loop call counts, injected-vector hashes, outside-readout preservation, donor IDs, CPU RAM and per-forward timing/GPU window peaks are retained.

`fp32_sdpa_bf16_writeback` means FP32 calculation of the full-shaped hybrid SDPA followed by BF16 injection into the otherwise BF16 model; it is not a full FP32 model forward. `scores_bf16_sensitivity` is a separate scoring-only sensitivity calculation and is not the production score.

GPU peaks in per-forward rows cover those measured windows. Report the maximum across all native/intervention rows; the final receipt's GPU fields alone describe only the last measured window. GPU allocations during model loading, between-forward hybrid derivation and serialization are outside those recorded windows, so this is not a full-collector GPU peak. CPU maximum RSS is process-wide. Receipt wall time begins after input/model-file hashing and includes model loading and collection/replay; UTC launch timestamps provide the larger command window.

Technical two-item outputs, the balanced 64-item Train discovery pilot, and complete 299-item Validation runs use separate namespaces. Original KV299 follows the frozen Train pilot; subsequent Q/R/late299 are exposed-cohort follow-ups because those operators were selected after inspecting earlier299 results. The preregistered128 questions were not used to choose these new causal operators, but they have historical full-cohort/eight-corner and possible peer-probe exposure: they are not globally unseen or blind. The balanced64 pilot is not a population estimate. The Test split is not rerun here. Original historical datasets, checkpoints, and previously audited runs are preserved.

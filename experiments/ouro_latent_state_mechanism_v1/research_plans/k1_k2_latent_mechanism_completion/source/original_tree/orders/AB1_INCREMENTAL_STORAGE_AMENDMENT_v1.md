# AB1 incremental storage execution amendment v1

This is an execution/storage amendment only, before any AB1 Train1030 or Validation299 forward. The original scientific order SHA 6b06d39d959084e72db0aa05570c15f913e3456301a6b24a97187e8f7fdbe8a8, primary correction SHA 8daa87cc677ff266e8909bc6da91b7901389fa86c0518ded80468001b08952a8, all14 endpoints, source identities, gold-free inference, fixed decoder, cohort IDs, original positive rescue route and no-tie criteria, controls, seed and analyses remain unchanged. The original whole-stage source/space freeze SHA cf20b040fc82273273d2c9b4b34a69c9e764cce0f118b96a6eea1fd6aebd1a52 remains immutable. No existing holdout case is migrated or overwritten.

Instead of reserving the maximum bound for the entire1030 before beginning, the single owner reserves enough free disk for min(16, remaining cases) times the observed maximum technical/discovery archive bytes times 1.35, plus 8 GiB for safe operation, audit metadata and subsequent analysis. The same rule applies independently to validation. Before every new question the running worker checks actual available disk against 8 GiB plus 1.35 times the observed maximum one-question archive and checks actual A6000 free memory >=20 GiB; it does not reserve GPU memory or stop other users. It commits each compressed lossless question pair atomically, with raw/archive/source hashes. If disk or GPU falls below the case limit between questions, it verifies model/source identity, writes and fsyncs an explicit suspension event, closes GPU model/lock on exit, and returns the distinguished resumable status. A new attempt may start only after strict independent recomputation of every existing pair's source identity, condition/control construction, saved values and score, and rechecking the next-batch reserve. If there is a partial file/orphan, it is preserved; the worker fails closed. A separate explicit tool, only after both project locks are available, moves safely identifiable partial/orphan paths into a same-filesystem quarantine with pre-move and done receipts; no deletion is allowed.

This no longer guarantees room for all1030 data at the first start. If cleanup/archive does not keep pace, the complete stage can pause indefinitely. It does not permit dropping any saved tensors or skipping the original independent per-question control math, saved full-vocabulary score replay, coverage audit, fixed Train analysis, or validation gates. Scientific summaries and holdout effects may only be read after their whole split is complete and audited. Unknown errors, source drift, orphan/partial ambiguity and wrong GPU are failures that stop the chain; no blanket retry and Restart=no remain. A full split proceeds only when each next batch is safe. Actual per-attempt wall time, resumed count, completed pairs and storage are recorded; do not add them to infer a pure GPU time.

The old whole-stage waiting service is stopped only while observed idle, and the new service uses the same exclusive supervisor lock and the same GPU lock. It may not start concurrently with the old owner. The old service, original freeze and all technical/discovery receipts remain preserved. The separate E2 CPU-only descriptive sidecar is re-bound to the new execution-source freeze and does not alter any frozen probe, training, intervention or scientific claim. The project user has authorized uploading and removing only independently verified unnecessary old data; this amendment does not itself delete, transfer or archive any data.

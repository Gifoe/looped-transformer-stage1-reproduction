## 固定 checkpoint 的原生拓扑

本地 `modeling_ouro.py` 与 `config.json` 的 SHA-256 分别为 `c5c68fbb368ce2909c257ae2afc50719be8c91539333d3295e19312c4316f413` 和 `ce9cc13da41591b8b4deca053d7dfee06424c0228628ee862ea86d725bc163f3`，与历史运行归档一致。据此核对了以下实际计算路径。 [运行归档](https://github.com/Gifoe/looped-transformer-stage1-reproduction/blob/521d71b00d09c8cafafa7541b9db9c43d3341719/experiments/ouro_hidden_computation_20261120/results/mechanism/runtime.json) · [检查点源码](https://huggingface.co/ByteDance/Ouro-1.4B/blob/574fa66cb8bf5abdc979642d01cf2b79b16bfab1/modeling_ouro.py)

- `OuroModel.forward` 只在 H0 构造 embedding，并在栈外构造位置、RoPE 和 mask。循环复用相同的 24 个层实例和轮末 RMSNorm，没有输入重注入。每层按 **Attention 残差写入 → MLP 残差写入** 执行，每轮 48 次相加。`current_ut` 在 Attention 中用于 `current_ut * num_hidden_layers + layer_idx` 的 cache 索引。固定上下文研究同时显式设置 `use_cache=False` 和 `past_key_values=None`。历史 `operator_confirmation.py` 在 tableau、twohop、ARC 各两题复用同一真实 K2 状态，交换 K2/K3 无 cache 上下文，48/48 个分支及 Anderson 终点逐位相同。该复核覆盖所测上下文。 [原生上下文互换](https://github.com/Gifoe/looped-transformer-stage1-reproduction/blob/521d71b00d09c8cafafa7541b9db9c43d3341719/experiments/ouro_continuous_embedding_20261120/operator_confirmation.py)
- Attention 的顺序为 `input_layernorm → q/k/v_proj → Q/K RoPE → 掩码和 softmax → A·V → concat → o_proj → input_layernorm_2 → 残差相加`。配置是 16 个 Q 头、16 个 K/V 头、每头 128 维，无滑窗。原实现 eager 路径的权重经 FP32 softmax 后转换成 Q 的 dtype，eval 时 dropout 为零。`OuroDecoderLayer` 丢弃 attention weights，融合 SDPA 可能没有显式物化 A。若用 eager 获得真实 A 或用 Q/K 重构 A，需记录路径并验证 `A·V`、`o_proj`、两次写入及完整 logits 的同精度误差。反事实在 head concat/O 投影前注入，保留投影、后置 RMSNorm、残差及同长原生后缀。 [Attention 源码](https://huggingface.co/ByteDance/Ouro-1.4B/blob/574fa66cb8bf5abdc979642d01cf2b79b16bfab1/modeling_ouro.py#L228)
- MLP 实际读取 Attention 写入后的状态。`post_attention_layernorm → SiLU(gate_proj) ⊙ up_proj → down_proj → post_attention_layernorm_2 → 残差相加`。隐藏宽度 2048，MLP 宽度 5632，投影均无偏置。互换位置应在 `down_proj` 前的乘积。Attention/MLP 两个三项分解的求和经过线性投影后成立至数值误差。后置 RMSNorm 对完整合成张量施加，独立归一化各分量会改变测量对象。需另报真实投影、Norm 及残差后的差。 [MLP 与层源码](https://huggingface.co/ByteDance/Ouro-1.4B/blob/574fa66cb8bf5abdc979642d01cf2b79b16bfab1/modeling_ouro.py#L368)
- `early_exit_gate` 每轮在轮末 norm 后读取隐藏状态，gate 输出进入退出概率和读出逻辑，下一轮直接接收原隐藏状态。固定深度计算应设核心 `total_ut_steps`，并读取对应 `exit_at_step` 的独立原生 LM head，其词表 49,152。`exit_at_step` 单独使用只控制从已执行轮次中选哪个读出，核心栈的实际计算预算由 `total_ut_steps` 决定。 [模型包装源码](https://huggingface.co/ByteDance/Ouro-1.4B/blob/574fa66cb8bf5abdc979642d01cf2b79b16bfab1/modeling_ouro.py#L689)

## 本轮待验证的原生机制

现有证据确认同题候选行为可随深度改变，固定状态附近的算子换序产生可测方向，原生后缀可以利用人为移入的分离供体信息并产生有限交互。H1 信息积累、H2 状态依赖路由和 H3 读出边界转换仍与这些观测相容。历史同一状态上下文互换只控制 Loop 标签，既有 patch 只说明替换成分可以被后续计算使用。

新机制证据需要从无标签的自然轨迹冻结候选，在相同后缀预算下分别测量自然 A/V 或 G/U 的双向因果作用，控制当前 margin、更新幅度、其他同剂量成分与答案读出。上一轮写入仍需以真实轨迹定位，验证该写入的定向移除和匹配恢复先影响下一轮 Q/K/Gate，再影响可观测的下游行为，并在独立题组重复。原生未改轨迹、原生干预后缀与人工连续模型由不同的证据链支撑。ARC validation 和 test 曾在项目中使用，继承数值只能作为复核对照。新的行为表应把无约束生成、完整候选答案 teacher-forced likelihood 和选项字母三个协议分别记录。

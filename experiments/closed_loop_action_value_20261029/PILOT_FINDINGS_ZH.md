# 闭环动作价值原型：实现检验

状态：原型可运行，机制有效性尚未建立。不是新的 benchmark 胜出结果。

在已暴露的 OpenBookQA discovery 前 8 题上运行冻结 Ouro-1.4B（官方固定 revision），于第 2 轮末的归一化状态施加动作，然后继续第 3、4 轮。动作控制器仅接收 prompt 和问题文本；所有候选共用先前确定的动作。原生四轮与零干预的所有深度状态逐元素相同；最终 Adaptive 候选分数相对封存流水线的最大绝对误差为 1.90735e-6。

三种非零干预在全部 8 题都改变了第 2、3、4 轮状态，而第 1 轮完全不变。参数版本计数保持不变且参数 requires_grad=False；没有进行训练。探针决策逐条本地重放一致。第一轮原始 167 个文件哈希保持一致。

输入探针变量选择了 6 次原样继续、2 次正向外推。没有选择完全回退或部分回退，因此这个小样本尚未展示自适应回退能力。Adaptive 基线、三个固定反馈动作及探针控制器都答对 5/8。8 题只用于实现检验：既不能证明收益，也不能据此否定这种机制。

运行主体耗时 30.36 秒，峰值 PyTorch 分配显存 2.698 GiB。成功工作进程完整区间 38.25 秒；首次启动失败按从请求创建到确认进程消失的 175.40 秒上界保守计费。本次合计 0.0593 GPU 保留小时；与第一轮合计 1.7557 小时，仍在原 8 小时上限内。这是实验计算账单，不是控制器的部署成本比。

本实现单独执行两轮 prompt 推理来选动作，随后执行候选评分；实验还枚举四个动作来记录反事实结果。不能从本报告宣称计算节省。没有 early stop，没有未暴露测试评估，没有训练 Quality Head，也没有全量开发任务在后台运行。

后续需用锁定的开发干预实验检验：输入探针收益是否对应真实后续答案收益；控制器是否优于固定动作、同触发率随机动作、置信度动作选择及仅改读出；变量打乱后是否丢失选择性优势。只有这些证据支持变量确有作用，才值得使用新的独立数据验证相对 LoopCD 的收益。

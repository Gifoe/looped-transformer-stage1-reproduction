# Reproduce the all-layer K1 route test

Use the public experiment dependencies listed in env.sh and the pinned checkpoint in results/VERIFICATION.json. Copy DECK.json into a fresh results directory. Run path_deck.py and then path_test.py with the local model directory and results directory as positional arguments. bash run_native.sh and bash run_paths.sh preserve the pre-inference protocol and exact source hashes in the server layout. report.py verifies the historical operand-pair ledger, fixed diagnostic subsets, entire generated integers and analysis files.

At every edited query, head and K1 layer, let \(a\) be its original attention row for the current receiving state. Removing mass \(d\) from a key set \(S\) multiplies those keys by \(1-d/\sum_{j\in S}a_j\) and renormalizes all weights by the remaining row sum. A complete operand cut uses \(d=\sum_{j\in S}a_j\). In the coupled pair, \(d\) is the smaller available mass across the operand-route stream and unrelated-keys stream at the same layer, head and query. Use the native value vectors and projections in both streams. Coupling sets intervention strength during an experimental forward and is absent from ordinary inference.

The complete joint cut leaves unchanged queries before the first digit of the second operand. Earlier queries, indirect reads through unedited token positions, residuals at source tokens and fresh reads in K2 are outside the eliminated edges. A null result therefore constrains the specified direct route family under the tested prefix and outcome. Pre-pivot and pivot restoration isolate the corresponding K1 output positions, at the K2 input. A paired statistical comparison of these restores requires actual joint-cut old errors. Complete reconstruction at those positions is the factual replay check.

The component analysis uses the parent decomposition of the four native and four counterfactual prefix states at the K2 physical layer 15 readout. Generated integer outcomes and diagnostic logits or norms are reported separately. K3/K4 interventions reuse the same K1 edit and each subsequent loop runs natively.
